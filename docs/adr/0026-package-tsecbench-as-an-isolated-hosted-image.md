# Package TSecBench as an isolated hosted image

CyberPenda will enter TSecBench through a separate, self-starting Docker image instead of a new product mode or a changed normal image. The hosted image will run the normal daemon and preserve Project, Task, Runtime, Skill, Blackboard, and policy semantics, while a hosted controller validates environment configuration, starts the evaluation automatically, completes all eligible challenge work, and exits. Shared packages may gain additive interfaces, but TSecBench-specific behavior must stay outside normal entrypoints and regression tests must prove that existing application, Sandbox Runner, Host Runner, Challenge Workflow, and startup behavior remain unchanged.

This choice makes the benchmark measure CyberPenda rather than a separate competition Agent. It accepts a larger hosted image and more orchestration work in exchange for behavioral fidelity and isolation from the normal product. One hosted run creates one CTF Challenge Project and one CTF Challenge Task. That Task's Runtime receives `BENCHMARK_BASE_URL` and `BENCHMARK_TOKEN`, loads a hosted-only TSecBench Skill, and owns the complete platform loop: list, start, solve, optional hint, submit, and close. The hosted controller only validates configuration, starts the daemon, creates and observes the Task, emits a non-sensitive summary, and exits. Challenge operations will not be routed through or added to Challenge Workflow or the trusted MCP.

The image selects one of a small verified set of model configurations from runtime environment values and fails before challenge work when configuration is invalid. TSecBench's score and completion state are the formal result; container-local Project, Blackboard, Evidence, database, reports, and logs exist only to support execution and diagnosis.
